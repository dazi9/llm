# 第四章 Transformer 块:RMSNorm、RoPE 与 SwiGLU

> 第三章的注意力负责"词与词怎么交流",但一个完整的 Transformer 块
> (`src/model.py:147-160`)还需要另外三样东西:让数值尺度稳定的东西(RMSNorm)、
> 让模型知道"词在第几位"的东西(RoPE)、以及让模型"思考"的前馈网络(SwiGLU)。
> 这三样加上第三章的注意力,就是一个 Block——然后把 12 个 Block 摞起来,
> 就是模型本体。

## 4.1 RMSNorm:给每个向量配一个"音量旋钮"

先看它的全部实现(`src/model.py:49-54`,只有 4 行):

```python
def forward(self, x):
    dt = x.dtype
    x = x.float()
    x = x * torch.rsqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)
    return (x * self.weight.float()).to(dt)
```

它做的事:把每个 token 的向量**除以自己的均方根**,再乘一个可学习的
缩放系数 `weight`。直觉:向量可以看作有"方向"和"长度"两个属性——
RMSNorm 把长度强制归一,只留方向给下游判别。长度是训练过程中最容易
失控的东西(它会随层数指数增长,最终淹没信号),控住它,深网络才稳。

三个实现细节,每个都有原因:

1. `x.float()`:bf16 训练时**必须**升到 fp32 再算均方根——小值的平方在
   bf16(8 位指数)下会下溢成 0
2. `+ self.eps`(在均值**内**):防止除零,位置错了测试对拍就过不了
3. 最后 `.to(dt)`:算完再降回 bf16,省一半显存

和原版 LayerNorm 的区别:不减均值(RMSNorm 不需要,减均值还会多一次
全量读写)、epsilon 在 RMS 内部。省的是参数和计算,稳的是训练——
这是 LLaMA 配方的核心选择之一。

## 4.2 RoPE:用"旋转"编码位置

问题:注意力本身是**无序的**——把输入的词序打乱,输出除了位置对不上
之外完全相同(数学上:注意力对输入集合是排列等变的)。模型必须被
明确告知"这个词在第几位"。

RoPE(Rotary Positional Embedding)的答案:把每个头的 64 维向量看作
32 个二维平面,**第 i 个平面旋转的角度正比于 位置 × 1/10000^(2i/64)**。
低维平面转得快(编码精细位置),高维平面转得慢(编码长程位置)——
像钟表的秒针、分针、时针。

实现(`src/model.py:56-87`)两步:

1. `_build`(69-75 行):预计算每个位置每个平面上的 cos/sin 表
2. `forward`(77-87 行):`x * cos + _rotate_half(x) * sin`——
   `_rotate_half`(56 行)把向量的前后两半交换并翻负,配合
   `cos = cat([freqs, freqs])` 的拼接,这就是"NeoX 风格"的旋转写法
   (HF LLaMA 同款;还有一种 interleaved 风格,数值不同但等价,
   我们的测试 `test_rope_reference_match` 钉死的就是这种约定)

RoPE 的杀手锏:**相对性**。位置 3 的 q 和位置 5 的 k 做点积时,
旋转只依赖 (5-3) 这个差值——注意力天然变成"相对距离敏感"。
这就是它能外推到训练时没见过的长度的原因(第五章的 tiny 模型用
512 训练,采样时给 1024 也能凑合工作)。

## 4.3 SwiGLU:让前馈网络学会"开门"

`src/model.py:136-145`:

```python
def forward(self, x):
    return self.w2(F.silu(self.w1(x)) * self.w3(x))
```

三个矩阵,两个分支:w1 分支经过 SiLU 激活(w1x > 0 时放行,类似"开门"),
w3 分支是线性"门控信号",两者逐元素相乘——**门开着才让信息流过 w2**。
直觉:每个 d_ff 维的通道都是一个"特征检测器",SiLU 决定"检测到了吗",
w3 决定"这个检测重要吗"。

为什么是 8/3·d 而不是 4·d?因为 SwiGLU 有三个矩阵而 GELU-MLP 只有两个,
要参数量持平就得把宽度缩到 2/3:8/3·d 与 4·d 的参数量几乎相同
(本章习题 2 算这笔账)。`src/model.py` 的 `_dff()` 把它对齐到 64 的倍数
——对齐让 GPU 的矩阵运算落在最优 tile 上。

## 4.4 Block:三明治结构(`src/model.py:147-160`)

```python
x = x + self.attn(self.norm1(x), rope)   # 交流:和别的词交换信息
x = x + self.mlp(self.norm2(x))          # 思考:每个词独立地消化
```

两个残差支路 + 两个 pre-norm。残差(`x = x + ...`)的意义:每层只学
"对当前表示的**修正量**",而不是重新表示——梯度可以直接穿过加法
流回浅层,这是深网络能训练的前提。pre-norm(先归一再进支路)让
修 正 量 的 尺 度 从第一层起就被控住——post-norm 的老式结构必须靠
warmup 续命。我们的消融没测 norm 位置,因为 2020 年之后这已经
不用测了:pre-norm 是唯一 sane 的选择。

nanoGPT/GPT-2 的残差初始化技巧(把支路末端的投影初始化为
0.02/√(2L))在本项目里以 `residual_init_scale` 开关提供
(`src/model.py:170-178`),默认关闭——消融留给你,见第八章。

## 4.5 自己动手

**动手 1**:验证 RMSNorm 只改长度不改方向:

```python
import torch, sys; sys.path.insert(0, "src")
from model import RMSNorm
norm = RMSNorm(64).eval()

y = norm(x)
print(torch.cdist(y / y.norm(dim=-1, keepdim=True), x / x.norm(dim=-1, keepdim=True)).max())
# 期望:≈ 0(方向余弦完全一致;weight 全 1 时不改变方向)
```

**动手 2**:观察 RoPE 的"时钟"(这是理解外推的关键):

```python
from model import RotaryPositionalEmbedding
rope = RotaryPositionalEmbedding()
x = torch.randn(1, 1, 16, 8)      # 单头,8 维
lo = rope(x[..., :2])             # 低维平面(转得快)
hi = rope(x[..., 6:])             # 高维平面(转得慢)
print((lo[0,0,7,0] - lo[0,0,3,0]).abs().item())  # 跨 4 个位置,变化大
print((hi[0,0,7,0] - hi[0,0,3,0]).abs().item())  # 同样跨 4 个位置,变化小
```

## 4.6 踩坑记录

- **bf16 下不做 fp32 upcast**:RMSNorm 均值下溢,loss 会莫名其妙地
  稳定在高位不降——本项目的 RMSNorm 一开始就写对了,但这个坑
  在 HANDOVER 里排第 13 位,因为它是"新手自己实现时"的高频翻车点
- **RoPE 两种约定不能混**:interleaved 与 half-split 数值不同,
  混用在导出 GGUF 时会静默产生错误模型(本项目的约定钉在
  test_rope_reference_match 里)
- **qk-norm 进了模型就出不去**:GGUF 转换不认——见第三章 3.6
