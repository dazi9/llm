# 第三章 注意力:一个会"查字典"的函数

> 上一章结束时,文字已经变成了 0 到 31999 的整数序列。本章讲整个
> Transformer 里唯一"聪明"的部分:**注意力(attention)**——
> 一个让每个位置"环顾四周"并按需取用信息的机制。代码在
> `src/model.py:90-134`,全文不足 50 行,但它是 GPT、LLaMA、Qwen
> 以及本项目的核心。

## 3.1 直觉:每个词同时当"读者"和"字典"

想象读这句话:"小追把球扔给了小**皮**,因为**它**泄了气。"

读到"它"时,你的大脑需要决定:"它"指的是球还是小皮?(答案是球,
因为泄气的是球。)注意力的机制就是把这个过程程序化:

1. 每个位置生成三份拷贝,身份各不相同:
   - **Query(查询)**:"我在找什么?"
   - **Key(键)**:"我能提供什么?"
   - **Value(值)**:"我的实际内容"
2. 每个位置的 Query 与**所有位置**的 Key 做点积——点积大 = "你正是我要找的"
3. 打分归一化(softmax)后,按权重把所有位置的 Value 混合过来

"它"的 Query 和"球"的 Key 撞出高分,于是"它"的表示里就混入了
"球"的 Value——**一个位置的表示,从此包含了别的位置的信息**。
这就是"注意力"这个名字的全部含义:按需分配注意力。

## 3.2 代码逐行:`Attention.forward`(`src/model.py:108-134`)

先看形状变换(109-112 行):

```python
q = self.q(x).view(B, S, self.n_heads, self.d_head).transpose(1, 2)
```

三件事:线性投影(768 维 → 768 维,但按 12 个头切成 12 份 64 维)、
view 重排、transpose 换轴。结果 q/k/v 都是 `(B, 12, S, 64)`:
**每个头独立拥有一个 64 维的小注意力**。为什么要多头?12 个头可以
同时关注不同类型的关系——一个头追指代,一个头追句法,一个头追语义。

因果掩码藏在哪?在 `sdpa` 路径里只用了**一个参数**(`src/model.py:124`):

```python
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

`is_causal=True` 生成的下三角掩码保证了:位置 i 只能看 ≤i 的位置。
这就是为什么第一章的测试(`test_causal_attention_independence`)
能验证"改未来不影响过去"——训练语言模型时,这条规则让
"预测下一个字"成为可能(如果模型能偷看答案,它就什么都不用学)。

naive 路径(126-129 行)把这个黑盒拆开写:score = q@k/√d,
上三角填 -inf,softmax,乘 v——**数学上与 sdpa 完全等价**,
但显存里真的放下了那个 S×S 的大矩阵。两条路径的对比就是
第六章 FlashAttention 的一整个故事。

## 3.3 QK-Norm:我们消融实验的胜者

`src/model.py:115-118` 是本项目消融实验(ch08)的胜者:

```python
if self.q_norm is not None:
    q = self.q_norm(q)
    k = self.k_norm(k)
```

在 RoPE 之前对 q、k 做 RMSNorm,把每个头的向量长度拉回统一尺度。
直觉:q 和 k 的长度会随训练自由增长,长度大 → 点积大 → softmax
接近 one-hot → 梯度消失。归一化长度等于给注意力"控温"。
消融数据:val 1.5974 vs 基线 1.6294,三个学习率下排序一致
(`reports/ablation.md`)。

## 3.4 GQA:省显存的"组查字典"

`src/model.py:120-122`:

```python
if self.n_kv_heads != self.n_heads:
    rep = self.n_heads // self.n_kv_heads
    k = k.repeat_interleave(rep, dim=1)
```

多头注意力的 k、v 投影占了每层 1/4 的参数。GQA(MQA 的推广)让
多个查询头**共享**同一组 k/v:`n_kv_heads=2` 时,12 个头共用 2 组键值,
参数省 393K,推理时 KV cache 省 6 倍。我们的消融里它排第二
(1.6206)——质量损失小到可以忽略,收益在大模型/长上下文里兑现。

  就是防这个的
